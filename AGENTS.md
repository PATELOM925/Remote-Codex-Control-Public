# Rules for coding agents

These rules apply to any coding agent that changes this repository. Read [CONTRIBUTING.md](./CONTRIBUTING.md) for the full workflow.

## Before you finish

- Run `npm run verify:quick`. Fix every failure before you report the work as done.
- For a docs-only change, run `npm run secrets:check`.
- Check `git status --short` and make sure only the files you meant to change are listed.

## Never commit

- `setup.md`, `.env`, or any `.env.*` file that has real values.
- `.dist/`, SQLite files, logs, token files, or runtime screenshots.
- Real bot tokens, relay tokens, chat IDs, or local folder paths in code, tests, or docs.
- Commit trailers, "generated by" lines, or names of AI tools in commits, pull requests, or docs.

## Keep these boundaries

- Telegram is the only supported operator interface. Do not present the web console or the relay as a setup path.
- Do not weaken the chat allowlist, the approval expiry and supersede checks, idempotent callbacks, path confinement for uploads and artifacts, redaction, or the localhost bind of the status server.
- Do not widen file or network access without a policy and a test.
- Do not let an upload skip thread scoping.
- Do not let an expired or superseded approval resolve.
- Do not add a path that pushes to `main`.
- Do not claim access to hidden reasoning.

## Change style

- Make small changes, and add or update a test for each behaviour change.
- Keep the App Server, Telegram transport, state, artifacts, file intake, and Git guardrails in separate modules.
- Match the plain, direct style of the existing docs. Do not use marketing words or em dashes.
